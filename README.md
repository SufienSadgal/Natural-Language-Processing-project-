## 🎯 Project Objective
This project involves developing an autonomous conversational agent designed to compete in **"Who wants to be a PoliMillionaire?"**, a timed online quiz game.
* **Latency Constraints:** The chatbot must process the question, retrieve information, and generate the final answer within a strict 30-second time limit.
* **Local Infrastructure:** According to the competition rules, all models must be "open-weights" and run entirely locally, preventing the use of paid APIs like OpenAI. The entire stack was optimized to run on a Google Colab T4 instance (15 GB VRAM).
* **Multi-Modal Interface & Domains:** The system supports textual and audio interaction (ASR via Whisper) to answer questions across multiple domains, from history and current events to complex logical-mathematical problems.

## 🔍 RAG (Retrieval-Augmented Generation) Pipeline Development
To tackle factual questions, we implemented a highly asynchronous two-stage RAG pipeline:
* **Query Construction:** Questions undergo stripping of useless prefixes (e.g., "What is...") and, via an LLM, are rewritten into synthetic 5-10 word queries. "Entity queries" (capitalized keywords) are also extracted in parallel to direct searches on Wikipedia.
* **Parallel Retrieval & Chunking:** Simultaneous scraping is performed via *DuckDuckGo Text/News* and *Wikipedia* (via `trafilatura`). The retrieved documents are then split into overlapping 3-sentence windows (approx. 800 characters).
* **Bi-Encoder Prescoring (Filtering):** To handle large volumes of chunks without hitting bottlenecks, texts pass through an `all-MiniLM-L6-v2` model that calculates cosine vector similarity, ultra-fast filtering the top 80 chunks.
* **Cross-Encoder Reranking & Gating:** A heavier model (`ms-marco-MiniLM-L-6-v2`) performs final reranking by comparing candidate chunks simultaneously against the question and the 4 options. A logical "gate" system (minimum threshold of 1.5) prevents out-of-context glossaries from entering the prompt.
* **Audio Adaptations (Speech RAG):** To manage the physiological delay of audio (options are not immediately available), the RAG is bi-phasic: it starts retrieving cognitive background based on the question alone and launches a second targeted search as soon as the options are transcribed.

## 🧠 Model Selection and Mathematical Domain Focus
The choice of the language model was crucial to balance the quality of reasoning (*Chain-of-Thought*) and speed to avoid the 30-second timeout.
* **Model Exploration:** 
  * *DeepSeek Math 7B*: Discarded due to excessive verbosity (tendency for continuous self-critique), which saturated the available time.
  * *Qwen Math 7B*: Discarded due to "amnesia" phenomena (losing the train of thought before the answer).
  * *Mistral 7B*: Purely mathematical performance was sub-optimal.
* **The Chosen Model:** The core of the agent relies on **Qwen 2.5-14B Instruct**, which demonstrated maximum stability and the best balance between quality and generation speed (run in GGUF format with a llama.cpp backend).
* **Tool-Calling Strategy for Math:** Providing documents via RAG to mathematical models compromises their internal deductive reasoning abilities. For this reason, for math quizzes, RAG is **bypassed**. Instead of forcing the model to perform complex arithmetic calculations internally, the agent is instructed to generate Python code to solve the questions. The environment executes the generated code, extracts the exact result, and proceeds to map it against the available options, bypassing the intrinsic computational limits of LLMs.

## ⚡ Architectural Optimizations and Prompt Engineering
To perform fast inferences with a 14B model on a single 15 GB T4, the architecture was maximized in every aspect.
* **Optimized Architectures:**
  * **AWQ (Activation-aware Weight Quantization):** Used to compress model weights. AWQ faithfully preserves the 1% most critical parameters upon activation, offering performance nearly identical to float16 weights while drastically reducing VRAM usage.
  * **GQA (Grouped-Query Attention):** Leveraging strategic Key-Value groupings, this attention type reduces the memory footprint of the KV Cache. This heavily increased inference speed on long sequences generated by the RAG.
  * **RoPE (Rotary Positional Embeddings):** Integrates more robust positional identification, maintaining high attention and generalization over a context window that was constrained to 8192 tokens (to avoid premature RAM saturation).
* **Orchestration with DSPy:** Instead of resorting to complex and fragile manual prompts, we used DSPy. Through typed "Signatures" in Python, the framework manages the injection of RAG context and models the LLM outputs (forcing the return of the exact final index).
* **Dynamic Prompting and "Phonetic Bridge":** The system rotates through different System Prompts depending on the competitive track. Special mention goes to the **Phonetic Bridge** developed for Audio Tasks: since ASR (Whisper large-v3-turbo) often produces noisy or corrupted transcriptions (e.g., transcribing the option "mass" as "ass"), the prompt forces the LLM to process the theoretical answer even before looking at the options, and then to phonetically match the corrupted strings to its logical prediction.
